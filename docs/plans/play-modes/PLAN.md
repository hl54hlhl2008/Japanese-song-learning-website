# 网页歌词列表播放模式计划

本文记录已验收的播放模式与复审修复。功能提交为 `ae292bf`，修复提交为 `b5e0369`，两者已进入项目 fork 的 `main`。本次文档提交归档实现范围、取舍与验收，后续实施须经用户确认。

## 实施前的行为

从基线 `fdfbdea` 看，单句播放一次和单句循环共用 `playLine`、`pendingClipRef` 和 `startClipPlayback`。起点是目标句时间戳提前 0.5 秒，最低为 0。终点优先取紧邻下一句的有限时间戳，其次取音频时长，时长未知时用起点加 8 秒。起播后由 `playingLineId` 标记目标句。片段到达终点时，单次播放停止，循环播放跳回片段起点。

安卓跟唱用 `continuousPlaybackRef` 进入连续播放，从文件开头或指定句起播，通过同一个 `<audio>` 的媒体事件按时间戳推进高亮，持续到文件结束。

## 已验收的行为

- 桌面和手机网页的歌词列表提供「单句」与「从开头播放到当前句」。桌面用行内播放按钮，手机网页也可点击整句。逐句练习、复习和安卓客户端沿用各自原有入口。
- 新模式从音频 0 秒开始，终点取目标句后第一个严格更晚的有效时间戳。同时间戳共用终点。末句播到文件结束，时长未知且没有下一句时等待音频自然结束。
- 新模式保留 0.12 秒的最小片段规则，已知音频时长优先作为上限。时长不足 0.12 秒时，终点截断到实际时长。
- 两种模式共用逐句倍速。再点正在播放的目标句暂停，下一次从当前模式的起点重播。模式切换会停止当前片段并取消待播请求。播放标记对应触发播放的目标句。
- 刷新网页后默认单句。循环只对单句生效，切回单句时恢复保存的循环偏好。等待元数据期间修改循环，首个片段使用最新设置。

## 取舍与翻转条件

| 决策 | 取舍 | 翻转条件 |
| --- | --- | --- |
| 新模式只进网页歌词列表 | 复用现有列表入口，练习、复习和安卓各自保留原有交互。 | 用户明确要求覆盖某个其他入口，并给出该入口的播放和暂停规则。 |
| 复用片段执行路径 | 两种模式共用元数据等待、跳转、倍速和停止机制。区间及按钮判断可单测，媒体副作用留在应用入口。 | 新模式需要跨多个片段自动推进，或需要按实际音频进度逐句更新播放标记。 |
| 0 秒起播，以下一个有效时间戳为句尾 | 包含前奏。LRC 暂只有句首时间戳，重复时间戳共用同一个句尾。 | 用户明确要求跳过前奏，或歌词来源提供可信的独立句尾数据。 |
| 已知音频时长优先 | 保留正常音频的 0.12 秒下限，同时让极短音频的终点落在实际文件内。 | 产品明确要求把无有效播放区间的素材标为不可播放，并约定提示和入口行为。 |
| 默认单句，循环偏好沿用原设置 | 刷新后行为可预测，用户仍可切回原来的循环设置。 | 用户要求跨会话记住模式，或明确要求重复播放从开头到目标句的整个区间。 |
